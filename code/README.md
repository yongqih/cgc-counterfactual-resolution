# CGC scientific sources, integrity checks and table generator

Run each Python entrypoint from the release root with Python 3.10 or later. The 17 Python wrappers use only the standard library and check selected scalar values and/or row counts in released CSVs. They do not download or relicense third-party inputs, refit models, regenerate predictions, resample results, or render figures.

Actual capabilities are declared in `PUBLIC_CODE_MANIFEST.csv`. Every existing Python wrapper is a `NON_REPRODUCTION_INTEGRITY_CHECK`; intended reconstruction capabilities are not implemented by those wrappers. Successful JSON output therefore uses `status: integrity_check_passed`, `entrypoint_classification: NON_REPRODUCTION_INTEGRITY_CHECK` and `scientific_reproduction: false`. The legacy output directory name `reproduced/` is retained only for path compatibility.

Actual scientific implementations are now exported separately in [scientific/](scientific/README.md). They include exact immutable source blobs, local dependency closure, configurations/splits, source hashes, explicit input contracts and an execution-guarded launcher. These are not the 17 wrappers renamed. Read each bundle's runtime contract before execution: prepared data are external, and the T-cell1B/1D originals require genuine historical Git provenance and CUDA. The included smoke tests do not constitute real-data analysis reruns.

Active State and Resolution-v2 routes use only the already-adjudicated current definitions; obsolete sampled-null and invalid random-projection all-stage routes are blocked. Old context-only ED7 finalizers are also not allowlisted. Original source remains immutable historical evidence, not an invitation to reintroduce superseded inference.

Despite its name, `figure_generation` checks only the complete current CSV package for Main Figures 1–6, Extended Data Figures 1–9 and Supplementary Figures 1–5. Passing the wrapper establishes released-table presence and frozen row-count integrity only; it does not regenerate scientific values or figures. The `supplementary_tables` Python wrapper similarly checks the six tabular sources.

Separately, `supplementary_tables/build_workbooks.mjs` is a genuine `TABLE_GENERATOR` using Node.js and `@oai/artifact-tool`. It regenerates the six formatted XLSX workbooks from the released table-source CSVs, not their upstream scientific results; see its README. The author-tested runtime is a declared dependency, not an assumed publicly available package. Table-source CSVs remain independently readable. The local author-provided Figure 1a asset remains unchanged and is not regenerated by this code.
